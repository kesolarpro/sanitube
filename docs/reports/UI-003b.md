# UI-003b — Catalogue: artists

The artist list and detail, following the pattern UI-003a established and had
validated.

## Scope, stated

UI-003b as scoped covers artists, contributors, compositions and assets. **This
PR delivers artists only.**

Artists first because they are the entity every other catalogue screen links
to. Contributors and compositions are structurally the same shape and become
cheap once this is reviewed; **assets are deliberately last**, because the asset
detail carries the preview-URL decision, and that is a security boundary rather
than another list.

**Remaining, tracked as UI-003c:** contributors, compositions, assets.

## What it inherits, deliberately

Every guarantee from the track screens holds here, by construction rather than
by coincidence:

- **Active identifiers only**, scoped at the read-model boundary — never a
  global scope on `ExternalIdentifier`, so audit and reconciliation code can
  still ask for revoked rows. `a_revoked_identifier_is_not_presented_as_current_identity`
  asserts both halves.
- **Filters refused, not ignored.** `ArtistIndexRequest` answers 422; the read
  model throws for non-HTTP callers. The form renders the validated canonical
  values.
- **Cursor ordered by `(name, uuid)`**, shape-checked so a mangled URL is a 422
  rather than a 500 inside the paginator.
- **No internal key** in any payload, and route binding on the UUID.

## What is specific to this screen

**Counts are aggregated, not fetched per row.** `withCount(['tracks', 'releases'])`
puts both numbers in the list query; asking per artist would be two round trips
each. `listing_more_artists_does_not_cost_more_queries` asserts the cost is flat.

**The track list on the detail is capped at 50, and says so.** `tracks_truncated`
and `tracks_shown` travel with the payload. A page showing fifty of nine hundred
tracks with no note reads as an artist with fifty tracks — the cap has to be
visible, or it is a lie by omission.

## Tests

**15 new tests. 660 PHP tests / 2497 assertions**, 1 skipped (the real ffprobe
run), plus 16 component tests.

Two of my own test bugs were fixed rather than the code: a helper creating the
same user twice inside one test, and — carried over from UI-003a — the fact that
AST-001's unique index forbids two active identifiers in the same namespace, so
a "revoked and current" pair must differ by namespace.

## Localisation

All new strings in en / fr / es / it / pt / de, including the artist-type
vocabulary and the new navigation entry.

## Architecture amendment

**None.** Both read models only read.

## Carried-over limitation

Unchanged from UI-003a and still true here: a refused filter answers 422 with a
JSON body rather than an error rendered inside the filter form. Refusing loudly
is the behaviour that must not regress; presenting the refusal nicely is a
follow-up on the filter form itself.
