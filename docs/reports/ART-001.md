# ART-001 — Artwork is measured, and judged on what was measured

Before this ticket a release cover was validated on two things: that its asset
record said `ARTWORK`, and that its checksum had verified. Both are properties
of the *record*. A cover could satisfy both and be a 600×400 CMYK TIFF that no
store accepts, and nothing in the platform would have said so.

---

## The bug this found on the way

`assets.width` and `assets.height` are columns **nothing in this platform has
ever written.** No service, no importer, no analyser. They are null on every
production installation.

Three screens read them — the release detail, the asset detail and the release
artwork picker — so all three displayed a blank dimension beside a verified
checksum, which invites a reader to believe the platform checked something it
did not.

**The suite did not notice because `Asset::factory()->artwork()` sets
`width => 3000`.** Every test looked at a perfectly-sized cover that had never
existed. That is the shape of defect this session keeps finding: a fixture
supplying the answer the code was supposed to produce.

All three read sites now ask `MeasuredDimensions`, which reports null until
something has actually looked. The dead columns are left in place — dropping a
column is destructive and belongs to its own deliberate ticket — but nothing
reads them.

---

## What was built

A new `Artwork` module, registered in `config/sanitube.php`.

**`ImageMeasurer`** — a contract, with `NativeImageMeasurer`,
`UnavailableImageMeasurer` and a shipped `FakeImageMeasurer`.

The native one uses `getimagesize()`, **deliberately not GD and not Imagick**.
It lives in ext-standard and is present on every PHP build including the shared
hosting this platform targets, and it reads the header rather than decoding, so
a large cover costs a few bytes of I/O rather than its full size in memory.

What it cannot do is read an embedded colour profile, so "is this sRGB" is a
question it does not answer and does not pretend to. It reports the channel
count, which separates CMYK from RGB for JPEG and says nothing at all for PNG.

**`ArtworkMeasurement`** — MEASURED in ADR-0016's sense. `isCmyk()` returns
`?bool`, and the null is the point: a PNG records no channel count, so answering
`false` would assert something nobody measured.

**`ArtworkAnalysis`** + migration — the same separation `audio_analyses` makes,
unique on `(asset_id, measurer, measurer_version)`, so re-measuring is
idempotent and a better measurer adds a row beside the old one.

**`MeasureArtwork`** — streams the object to a temporary file, measures, removes
it in a `finally`. Refuses non-artwork and unverified assets.

**`ValidateArtwork`** — judges a stored measurement against configurable
requirements. It measures nothing itself: validation runs every time a release
screen is drawn, and streaming a cover from object storage on each of those
would make a page load an object-storage bill.

**`config/artwork.php`** — every requirement configurable, zero or null meaning
"no requirement", **and no distributor named anywhere in the file or the code
that reads it.** Stores disagree at the edges; an operator delivering somewhere
with different rules changes a number rather than patching a validator.

Plus a queued job, a listener on `AssetVerified`, and
`sanitube:artwork:measure` — the backfill that makes `COVER_NOT_MEASURED` a
waiting room rather than a dead end, since covers verified before this module
existed will never trigger the listener.

### Four states, not two

| State | Outcome | Why |
|---|---|---|
| Measured and conforming | nothing | |
| Measured and not conforming | **error**, with the measured value in the context | So a person sees *why* rather than being told to try again |
| Measured and unreadable | **error** `COVER_UNREADABLE` | Somebody looked and it is not an image |
| Not measured | **warning** `COVER_NOT_MEASURED` | Nobody has looked — never a pass |

The third and fourth are the ones that matter. Collapsing them would turn a
corrupt cover into a suggestion; reporting the fourth as a pass is how a release
is delivered with artwork that had simply never been checked. And it is a
*warning* rather than an error because an installation that cannot measure
images would otherwise report every release as broken — the same reasoning that
keeps a missing audio analysis from blocking a catalogue.

**The minimum is about the shortest side, not the width.** A 4000×1000 image
satisfies "at least 3000 wide" and is not usable as a cover. That is the case a
naive check gets wrong and it has its own test.

## §1 — the two proofs

**A. COMPONENT PROOF.** `tests/Feature/Artwork/ArtworkValidationTest.php`,
22 tests / 55 assertions. Real PNGs are written and measured rather than
described — the whole point of the module is that a dimension comes from a file.

**B. PRODUCTION-PATH PROOF — who calls this in production?** Four callers, each
asserted:

- **The observer.** Reaching `VERIFIED` emits `AssetVerified`, and the listener
  queues the job. **No event is dispatched by hand in that test**: reaching the
  verified state *is* the trigger, and a test that fired the event itself would
  prove the listener works without proving anything ever calls it. A verified
  master queues nothing.
- **`ValidateRelease`**, which the release screen and the readiness gate both
  run. A validator nothing consults never stops a delivery.
- **`ReleaseDetailQuery`**, asserted with the misleading fixture in place: the
  test first checks `assets.width` really is 3000, so that "reports null" proves
  something.
- **`AssetDetailQuery` and `ReleasePickerQuery`**, the other two read boundaries.

### A17–A19 — three guards with no test behind them

I changed three read sites to use the measurement and tested none of them at the
query level. `MeasuredDimensions` had a unit test, which is not the same claim —
a guard nobody checks is indistinguishable from no guard the next time somebody
refactors. This is the third ticket running where mutation found exactly this,
and the pattern is now unmistakable: **wiring a service into a caller is a
separate claim from the service working, and needs its own assertion.**

The tests added are the strongest form available: they assert `assets.width` is
still 3000 *first*, so "the screen reports null" cannot pass vacuously.

### A14 — withdrawn against a redundant branch, with evidence

`ArtworkAnalysis::measurement()` guards on
`! $this->succeeded || $this->width_px === null || $this->height_px === null`.
Removing the `succeeded` clause survives, because `MeasureArtwork` writes null
dimensions on every failure — the two conditions are mutually redundant for
every state the service can produce.

Measured rather than assumed, before recording it:

- **A15 removes the whole guard and is killed**, so the guard is load-bearing;
  only that clause is not.
- **PHPStan is indifferent** to which half remains. I had expected the type
  system to require the null half and it does not, so that reasoning is not
  offered as the justification.

Killing A14 would need a row with `succeeded = false` and dimensions set — a
state nothing can produce, reachable only by writing to the table directly. That
is the brittle implementation test §2 forbids, so the mutation is **withdrawn**
and the clause stays as an explicit statement of intent.

One earlier redundancy was *removed* rather than recorded: `MeasuredDimensions`
originally re-derived "is this usable" with its own `where('succeeded', true)`
plus a null check. Two guards for one fact, where breaking either left the other
doing the work. It now asks `measurement()`, so the rule exists once.

## What this ticket did not do

- **No colour-profile inspection.** `getimagesize` cannot read an ICC profile,
  so "is this sRGB" is unanswered rather than guessed. It needs an image library
  this platform deliberately does not depend on.
- **No artwork upload or crop UI.** Covers are attached exactly as before.
- **The dead `assets.width` / `assets.height` columns are not dropped.**
  Destructive, and its own ticket. Nothing reads them now.
- **No per-distributor requirement sets.** One configured set. Naming
  distributors is precisely what the configuration exists to avoid.
