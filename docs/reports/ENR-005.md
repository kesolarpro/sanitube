# ENR-005 — the screen a person answers suggestions on

## Four levels, four columns, labelled

ADR-0016 draws three lines and the catalogue draws the fourth. This screen is
where a reviewer either sees that distinction or does not, and the whole ticket
is about making sure they do:

| Column | What it is | Where it came from |
|---|---|---|
| **In the catalogue** | Canonical | A person put it there |
| **Measured** | Facts | Read from the file by FFprobe |
| **Heard** | Proposed | A speech model that heard the audio |
| **Suggested** | Suggested | A language model reading a transcript |

**The four arrive as four separate objects from the server.** Nothing in the
bundle re-derives which level a value belongs to. DEDUP-003 settled that rule
for `is_measured` and the reason is the same here: a component that works out
the level for itself is a component that can drift from the domain, and this is
the one distinction the screen must not get wrong.

`what_a_model_suggested_never_appears_as_what_the_catalogue_says` is the test
that guards it, and a mutation that puts the model's title in the canonical
column dies against it.

## The empty column that must stay empty

`canonical` is **null when the asset masters no track**, and is never filled in
from the suggestion.

"Nothing yet" is the honest answer to "what does the catalogue say about this
recording", and null is how it is said. A column showing the model's guess
because there was nothing real to put there would be exactly the confusion the
four levels exist to prevent — and it would be invisible, because a plausible
title in a catalogue column looks like a catalogue title.

The same holds downward. `measured` is absent rather than zeroed when nothing
was analysed, and a **failed** analysis is not read at all: a failed row carries
whatever the analyser managed before it stopped, and putting that on screen
labelled as fact is worse than an empty column.

## Ordering, and the confidence that does not affect it

Ordered by `(suggested_at, uuid)` and by nothing else — **not by confidence.**

A queue that promoted confident answers to the top would teach a reviewer that
the rows near the bottom are the doubtful ones, which is a claim no model's
self-reported confidence supports. It would also move rows out from under
somebody working through a few hundred of them.

The confidence is shown, as a number, and used for nothing.

## What a reviewer can do

The four actions ENR-004 built, wired to their routes: **accept**, with the
title, language and genres editable in place; **reject**; and **ask again**.

Editing is the ordinary case rather than a special mode — the fields are inputs,
seeded from what the model said, not a form you have to open. The edits are held
beside the suggestion rather than over it, so the model's answer stays visible
next to the correction; a screen that overwrote the suggestion as you typed
would lose the only thing you were comparing against.

`accept` is disabled when there is no track, with the reason in the title
attribute rather than a refusal after the click. That is **presentation** and
stated as such in both the query and the component: the route middleware is the
permission check, and a disabled button is a courtesy.

## Containment

No path, no disk, no signed URL, no original filename — the same rule the asset
list and the duplicate queue hold. A storage layout published in page source is
one that can no longer be changed, and a durable link to a master is a leaked
master.

Asserted against the **query's own output with `JSON_UNESCAPED_SLASHES`**,
because DEDUP-003 discovered that reading rendered HTML hides a leaked path:
Inertia embeds props as JSON and `json_encode` escapes `/` as `\/`, so the raw
path never matches whether or not it is there.

## Translations

All six locales, in full, with the level notes translated rather than left in
English — the notes are the part that explains the distinction, and a reviewer
reading the platform in Portuguese needs them most. The parity test enforces
both directions, so a key added here and forgotten in Italian fails CI.

### Two defective tests, both mine, both found here

**The leak test was checking almost nothing.** It looped over three "secrets"
and skipped any that were not strings — and one of them, `object_key`, is a
property `Asset` does not have. So it silently checked two fields and reported
three assertions. PHPStan caught the typo and the mutation caught the
consequence; it now names each column individually and asserts each is non-empty
before asserting it is absent.

**A fixture applied overrides without saving them.** `forceFill($overrides)`
without `save()` hands back an object saying `REJECTED` while the table still
says `PROPOSED` — so every in-memory assertion passes and every query-side one
reads the wrong row. Four tests here failed on it at once, which is how it was
found. **The same fixture had already been merged in ENR-004**, where nothing
happened to depend on the difference; it is corrected in both files rather than
left as a trap for the next test written against it.

## Still not done

The refusal codes come back in the error bag and the screen does not translate
them yet — a reviewer sees `TRACK_RELEASED` rather than a sentence. The codes
are the right thing on the wire and the translation is a small, separate piece
of work.

There is no bulk action. Accepting forty suggestions is forty clicks, which is
the correct starting point for a screen whose entire purpose is that somebody
reads each one — but an installation running enrichment across a large library
will want a way to work faster, and designing that without re-introducing
accept-without-reading is its own problem.
