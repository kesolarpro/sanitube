# TRN-003 — the wiring, which is the whole ticket

## What was actually wrong

TRN-001 built the transcription contract, the storage and the refusals.
TRN-002 built the OpenAI adapter and proved a real request leaves for the
documented endpoint.

**Nothing called either of them.** `TranscribeAsset` had no upstream caller at
all — no event, no job, no command, no route. PIPE-001's grep said so out loud
one ticket earlier and TRN-002's report repeated it. On a real installation no
asset would ever have been transcribed, and both of those tickets would have
gone on passing their own tests forever.

So this ticket is the seams, and the tests are written against the seams rather
than the services: what does storing an asset actually cause, what does
pressing the button actually queue, and what does the queued job actually do
when a worker reaches it.

## The one enrichment that costs money

Everything else that follows a stored asset is free and local — a checksum
comparison, an acoustic fingerprint. Deduplication therefore listens to two
events and always runs.

Transcription is a paid call to somebody else's server, per file. Wiring it the
same way would mean a library of four thousand masters spends four thousand
calls before anybody has read the first transcript, and **no existing ceiling
would stop it**: OPS-002 guards the depth of the queue, not an external bill.

So `transcription.automatic` is **off by default**, and that default is the
design rather than caution. The platform transcribes what somebody asks for,
and an operator turns automatic transcription on once they know what a
transcript is worth to them. The switch is tested from both sides — off must
queue nothing, on must actually work, or the switch is decoration — and the
shipped `.env.example` value is asserted directly, because CI and every fresh
install copy that file and AI-001 learned the hard way that what ships in it is
what actually runs.

## Three gates, asked in one order, in one place

`RequestTranscription` is the single entry point. The button, the listener and
the backlog command all come through it, so no caller can acquire the work
without acquiring the guards.

1. **`BackgroundWork`** — should this installation be doing anything at all?
   A person's decision.
2. **`BacklogGuard`** — is there room? A measurement.
3. **`TranscriptionEligibility`** — is *this file* worth sending?

Keeping the three apart is what lets an operator see which one stopped them. It
is also why the eligibility enum contains nothing about pausing or capacity:
folding them in would collapse three distinct answers into one unhelpful "no".

### The refusals

| Code | Why |
|---|---|
| `TRANSCRIPTION_PROVIDER_UNAVAILABLE` | No supplier, or no usable credentials. The ordinary state of a fresh install, and asked **first** so an operator with no key is told that rather than told their artwork has no speech in it. |
| `TRANSCRIPTION_ASSET_NOT_SETTLED` | The write is still happening. A supplier reading a truncated object returns a confident transcript of half a recording, which is worse than none. |
| `TRANSCRIPTION_ASSET_TRASHED` | Somebody set this aside. Paying to transcribe a file a person has already rejected is the clearest waste available. |
| `TRANSCRIPTION_NOT_AUDIO` | Artwork, documents, distribution exports. |
| `TRANSCRIPTION_ALREADY_HELD` | Held at this provider and this version. A version bump makes it eligible again, which is the point of versioning it. |
| `TRANSCRIPTION_CONFIRMED_DUPLICATE` | A person has confirmed this is a copy of something already held. |

Every one of these is an **ordinary state, not a failure**. A library where
most assets are refused is a library working correctly.

Two of them are narrower than they first look, deliberately:

**Only `CONFIRMED` duplicates are skipped.** A proposed finding is a question
nobody has answered, and refusing on one would let an unreviewed similarity
score quietly decide that a recording is never transcribed. And only *one side*
of a confirmed pair is refused — refusing both would leave the recording with
no transcript at all, which is worse than paying once.

**Video is not in the audible list**, and that is a decision rather than an
oversight. The path spools the object down and hands the supplier a file; a
video master is an order of magnitude larger than an audio one. Sending video
is a cost decision that belongs to whichever ticket actually wants it.

## Eligibility is asked twice

Once when the work is requested, so a refusal reaches the person who asked and
no job is queued for something that was never going to happen — and again
inside the job.

**The second check is the one that protects the bill.** A queue is a delay, and
in it an asset can be trashed, transcribed by another route, or confirmed as a
duplicate. The job is the last point at which noticing that is free rather than
billed. A mutation removing it dies against a test that trashes the asset
between the request and the run.

An ineligible asset at that point is not a failure and does not raise: treating
it as one would fill the failed-jobs screen with assets somebody deliberately
trashed.

## The backlog command

`sanitube:transcription:backlog` is for the library that was imported before a
supplier existed — which, on an installation that has been running a while, is
all of it. It is the most cautious command in the platform, because it is the
one that really does cost money.

- `--limit` defaults to 100, and **0 means all**, as the signature says. A
  `--limit=0` that quietly queued nothing would be the most expensive silent
  no-op available: an operator would conclude the library was already done.
- `--dry-run` reports what would be sent and enqueues nothing.
- The missing-supplier case is **named**, not reported as "0 queued". Those two
  look identical to an operator and mean entirely different things.
- The admission gate is asked for the **whole batch**, once. Admitting one job
  at a time would let a sweep walk straight past a ceiling one asset at a time,
  with every individual admission legitimately succeeding.
- Nothing is enqueued before that refusal. A half-enqueued batch is work
  stranded where nobody is watching.
- Candidates are narrowed by the eligibility service, not by a second copy of
  its rules in SQL. Two versions of "should this be transcribed" would drift,
  and the one that costs money must not.

## The HTTP surface

`POST /assets/{asset}/transcription`, behind `can.role:catalogue`.

Reading a transcript is not a privilege; **causing a paid call to a third party
is**. The guard sits on the route so a future action cannot acquire the surface
without acquiring it, and a mutation that moves the route out of the group dies
against a member being refused.

A POST, because a GET would be prefetched by a browser and billed for the
privilege. Named for the act rather than for a status: `PATCH {status:
TRANSCRIBED}` would present a request to a third party as an assignment.

The controller decides nothing. It reads a hint and hands the asset to the
service that owns the gates — a controller that repeated those checks would be
a second, weaker copy of them, drifting from the one the queue enforces.
Refusals come back as codes; the English inside an exception is for a developer
reading a log.

The language hint is validated as a **code**, not free text. It is a hint and
never an assertion: the supplier reports what it heard regardless, and TRN-001
keeps both answers precisely so the disagreement survives.

## `AssetTranscribed`

The seam AI enrichment will hang off. An event rather than a direct call, so
Transcription stays ignorant of what a transcript is *for* — it knows how to
obtain one and where to put it, and nothing about genres, moods or
descriptions. The dependency points one way, exactly as `AssetFingerprinted`
keeps Media ignorant of deduplication.

It carries the transcript, not the text. A listener that wants the words reads
them from the row, which is also where the provider, the model, the version and
the segments are — an enrichment quoting a payload instead would have no way to
say which stored evidence it worked from.

It is not dispatched when there is no transcript. Announcing one that does not
exist would send enrichment looking for evidence nobody wrote.

### The harness was lying, and that is a finding

The mutation harness decided a mutation was killed by grepping its own output,
case-insensitively, for the word `fail`.

**Test names contain that word.** `automatic transcription does not fail an
upload…`, `a failing response body is never carried out of the adapter`, `a
transport failure is redacted before it is raised`. A run in which every test
passed still printed `fail`, and the harness read its own passing output as a
kill — so any mutation whose filter matched one of those tests was reported
killed regardless of what the code actually did.

It now reads the test runner's **exit code**, which cannot be confused with
prose. Every mutation in this ticket and in TRN-002 was re-run under it, and
`docs/reports/TRN-002.md` has been amended: two of its verdicts were false, and
its M10 genuinely survives that ticket's own test file (it is killed by
TRN-001's suite, which owns that refusal). The corrected claim is recorded
there rather than quietly fixed.

This is the third harness defect in two tickets — a filter matching no tests
read as "survived", a mutation that changed nothing read as a result, and now
this. All three fail loudly. **A mutation run that silently tests nothing is
worse than no mutation run**, because it is the thing you were relying on to
tell you the tests were real.

### Two genuine survivors, both fixed

- **N18** exposed a defective test of mine. `the_backlog_command_asks_the_
  ceiling_for_the_whole_batch` only exercised the *pause* switch, which refuses
  regardless of how many jobs are asked for — so it proved the gate existed and
  said nothing about the batch size, which was the entire claim in its name.
  Rewritten against a real ceiling with more eligible assets than room, plus
  the converse case where the batch does fit. The pause switch got its own test
  under its own name.
- **N24 and N26** exposed a real coverage gap: nothing tested `--limit` at all,
  on the one command in the platform that spends money per iteration. Both the
  bounded sweep and `--limit=0` meaning "all" are now asserted.

Neither was found by reading the code. Both were found by breaking it.
