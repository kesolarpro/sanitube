# REL-002 — Structured Release Validation

**Status:** delivered
**Base:** `9847158` (main, after DEP-002/003)
**Branch:** `claude/rel-002-structured-validation`

---

## What this ticket is actually about

Before REL-002, validation answered in English sentences. Those sentences
became a contract twice over, both times by accident:

1. The interface rendered them **verbatim**. A French label read
   `The cover asset must be ARTWORK with status VERIFIED.` — the platform ships
   six locales and validation was in one of them.
2. `SubmitDelivery` decided whether a distributor had been **unreachable** by
   searching one for a substring.

The second is the dangerous one, and it is the reason this ticket exists:

```php
// before
private function wasUnreachable(ReleaseValidationResult $verdict): bool
{
    foreach ($verdict->errors() as $error) {
        if (str_contains($error, 'could not be reached')) {
            return true;
        }
    }

    return false;
}
```

Reword that message — improve it, translate it, add a distributor name to it —
and an **outage silently becomes a rejection**. A rejection is a verdict: it
says the distributor looked at the release and said no. Nobody said no. The
delivery would have been marked rejected, the operator would have gone looking
for what was wrong with the release, and nothing was.

**A code is data. A message is for a log.**

## The shape

`ReleaseValidationIssue` — four fields, each earning its place:

| Field | What it is | Why |
| --- | --- | --- |
| `code` | `COVER_REQUIRED`, `DISTRIBUTOR_UNREACHABLE` | The contract. The only thing anything decides from. |
| `severity` | `ERROR` / `WARNING` | Whether it blocks. |
| `path` | `cover`, `tracks.1.4`, `label_name` | Lets an interface put the message beside the field rather than in a pile at the bottom. |
| `context` | `['number' => 4, 'disc' => 1]` | The **values** a translation needs — never a pre-formatted sentence, so every locale can use its own word order. |

`message()` still exists and is still English. It goes into logs, exceptions
and delivery-attempt records. What changed is that **nothing decides anything
from it**, and it is deliberately a method rather than a public property —
available where it is useful, awkward enough to reach for that nobody matches
on it by accident. That is exactly how the old contract formed.

`toArray()` — what travels to the browser — carries `code`, `severity`, `path`
and `context`. It does not carry the message.

## Severity lives on the issue

`ReleaseValidationResult` used to hold two independently-built arrays,
`errors` and `warnings`, which could disagree about which was which. It now
holds one list, and `errors()` / `warnings()` are **views** over it. They
cannot drift.

The result also deduplicates on `(code, path)`. Two validators finding the same
missing cover is one problem; a list that says it twice is a list somebody stops
reading. The same code about two different tracks is still two issues, which is
why the key is code *and* path rather than code alone.

## What the deduplicator revealed

`ValidateRelease` re-checked track releasability that `Release::readinessProblems()`
already reports — under a different `path` (keyed by track rather than by
release entry) and with different context keys. Deduplication is on
`(code, path)`, so it would have **slipped past** and told a label the same
thing twice in two different words. The redundant check is gone, with the
reason recorded where it was.

## The translation gate

`ValidationIssueTest` walks the source of `src/Releases` and `src/Distribution`
for every `ReleaseValidationIssue::error(...)` / `::warning(...)` call and
checks each code in all six locales — and the other direction too, so a
translation for a code nothing emits any more is caught rather than quietly
kept in six files.

Scanned rather than listed: a hand-kept list is one somebody forgets to add to,
and the forgetting is invisible until a person sees a raw `TRACK_NO_GENRE` on a
screen.

There is **no exemption list**. A list of codes that do not need translating is
a list somebody adds to instead of writing a translation. PHPStan flagged the
empty `in_array` check as an impossible condition, which was the right call —
it was removed rather than kept open.

A third check catches the other half: a translation asking for `:title` from an
issue that never carries one renders `:title` to a person. Cheap to check, and
invisible until somebody hits that exact validation.

### The scanner that passed while checking nothing

The context scanner first matched non-greedily to the first `);` — which is the
**inner `sprintf`'s** closing paren, not the constructor's. Every context came
back empty, every assertion passed vacuously, and the test looked green. It now
splits on the constructor and takes a fixed window. The comment in the file says
so, because a test that once checked nothing is worth a sentence of warning.

## Mutation testing

12 mutations injected, **12 killed**.

| # | Mutation | Killed by |
| --- | --- | --- |
| M1 | `SubmitDelivery` decides unreachability from a message again | `an outage leaves the delivery failed rather than stuck submitting` |
| M2 | An outage is recorded with the rejection code | same |
| M3 | `RELEASE_DATE_REQUIRED` downgraded to a warning | `a release with no date is blocked rather than merely warned about` |
| M4 | The result stops deduplicating | `issues are deduplicated by code and path rather than by message` |
| M5 | Deduplication ignores the path | same |
| M6 | The payload carries the English message | `the payload carries no english` |
| M7 | Severity is read from the wrong field | `severity lives on the issue…` |
| M8 | `has()` matches the path instead of the code | `a caller asks by code and never by message` |
| M9 | A code loses its context values | `a placeholder in a translation is supplied by the context` |
| M10 | A code is renamed without its translations | `every code the domain can emit is translated in every locale` |
| M11 | The sandbox warning becomes an error | `a sandbox distributor is warned about rather than blocked` |
| M12 | A missing ISRC stops being reported | `a track with no isrc blocks delivery and no isrc is minted` |

**M3 survived the first pass.** Downgrading "a release date is required" from
blocking to a warning changed nothing any test could see: `markReady()` refuses
on *any* problem regardless of severity, and nothing asserted that a dateless
release fails **validation**. It does now — and the assertion names severity
explicitly, because severity is what decides whether a release may be
delivered. A store handed a release with no date has nothing to schedule.

While fixing it, `marking_ready_is_refused_while_anything_blocks_it` turned out
never to have called `markReady()`. It does now, and asserts the refusal names
what is wrong rather than only that something was.

## Tests that got stronger without being rewritten

`ReleaseBuilderTest` and `DistributionTest` asserted on English substrings.
They now assert on codes. This is strictly stronger in both directions: the old
assertions went **green on a reworded sentence** and **red on a translated
one**, which is the wrong way round for both.

## Scope

No financial concept was introduced, referenced or navigated to. Validation
reports what a store will reject about a package; it says nothing about who is
owed anything.
