# UI-002 — Dashboard

The first business screen, built on the UI-001 design system.

## What it shows

Catalogue totals (tracks, releases, artists, compositions, contributors,
assets); tracks and releases by lifecycle state; ingestion candidates by state;
distribution deliveries by state; queue depth and failures; audio-analysis
activity; storage health with its individual probes; provider availability for
AI, music generation and every configured distributor; and the full system
capability report.

## The rule the screen turns on: unknown is not zero

An operator who reads "0 failed jobs" concludes the queue is healthy. If the
truth is that the table is absent or the probe threw, the dashboard caused that
wrong conclusion.

So every figure is `int` when it was counted and `null` when it could not be,
and the two render differently — a number against an em dash. The same applies
to providers: `available` is `true`, `false`, or `null` when the provider threw
while being asked, because a network blip is not a refusal and sends an operator
to a different log.

`DashboardTest::a_count_that_cannot_be_taken_is_null_and_never_zero` drops the
`failed_jobs` table and asserts the figure comes back null while the counts that
can still be taken are unaffected.

## Cost

`DashboardQuery` issues a fixed, small number of queries regardless of catalogue
size. Counts by lifecycle state are one grouped count each, expanded against the
enum in PHP afterwards — so a state with no rows renders as a real `0` rather
than vanishing from the list, and "no failed deliveries" stays distinguishable
from "the failed row fell out of the result set".

Nothing loads a model. The dashboard needs counts, and hydrating Eloquent
objects to count them is how a dashboard becomes the slowest page in an
application.

`the_snapshot_costs_the_same_whether_the_catalogue_is_small_or_large` counts
queries at two catalogue sizes and asserts they are equal. **It was verified to
fail against a deliberately injected N+1** before being trusted.

## No invented data

Every number comes from a `count()` against a real table, or from the last real
provider probe recorded by the scheduled refresh — see C1 below; nothing is
probed during the request. There is no sample data, no placeholder metric,
no figure computed in the browser, and no hardcoded activity feed. Buckets with
no rows are hidden rather than printed as zeroes — a delivery pipeline has
twelve states and an install typically uses three; nine zeroes bury the three
that matter.

## Routing

`/` is now the dashboard, registered by the Ui module with the rest of the
interface. The redirect that previously lived in `routes/web.php` is **removed**
rather than retargeted: two routes on the same URI would have a winner
determined by provider registration order. A guest is sent to sign in by the
`auth` middleware, which is where that decision belongs.

`routes/web.php` is now empty, with the reasoning recorded in it.

## Security

Unchanged and re-asserted: `/` sits behind `web` → `HandleInertiaRequests` →
`auth` → `active`, and `no_credential_reaches_the_dashboard` asserts no
credential-shaped value reaches the page. Storage failure detail is already
redacted at the `StorageHealth` constructor — the single place every failing
report passes through — so the dashboard displays it without re-deriving that
guarantee.

## Design system

Two additions, both in the one place that owns the decision:

- `StatusBadge` learned tones for `RELEASED`, `AVAILABLE`, `UNAVAILABLE`,
  `DEGRADED` and `OPTIONAL`. Without them an unavailable provider would have
  rendered in the same neutral grey as a draft.
- `status.generic` gained the nine status labels the dashboard renders, in all
  six locales.

No new primitive was needed, which is the result UI-001 was aiming for.

## Localisation

All new strings ship in en / fr / es / it / pt / de. The translation
completeness gate walks every file in `lang/en` in both directions, so a missing
or stray key fails the suite.

## Review correction C1 — no deep probing in a page request

The verdict was right: `GET /` called `StorageProvider::healthCheck()`, which
writes and deletes a probe object, plus provider availability calls that may
cross the network and a capability sweep that shells out. A page load doing real
I/O against five external systems is slow when they are healthy and
unresponsive when they are not — which is exactly when somebody opens the
dashboard to find out what is wrong.

**The probing moved out of the request cycle entirely.**

- `OperationalHealthProbe` performs the real probes. It has one caller path: the
  scheduled command.
- `sanitube:health:refresh` runs it and stores the result. Scheduled every five
  minutes — a deliberate floor, since each run writes and deletes a storage
  object. It exits 0 when providers are down, because a provider outage is a
  fact to record rather than a failure of the recording, and a cron job that
  emails every five minutes gets deleted. The one failure it reports is being
  unable to *store* what it found, since that leaves the previous snapshot
  looking current.
- `OperationalHealthStore` keeps the snapshot in the Laravel cache — `database`
  or `file` on the shared-hosting baseline. Redis works and is not required.
- `DashboardQuery` reads database counts live and external state from the store.

### Three states, and the third is the point

| State | Meaning | Verdicts |
| --- | --- | --- |
| `FRESH` | stored and recent | pass through as probed |
| `STALE` | older than `stale_after_seconds` | **every verdict forced to null** |
| `UNKNOWN` | nothing stored, or a snapshot that cannot be trusted | all null |

A snapshot from three hours ago is not evidence about now, so a stale `healthy`
is blanked rather than displayed. Names and probe details survive — they say
*what* was checked — but the verdicts do not, because those are assertions about
the present. `checked_at` is always exposed so the reader can judge the age.

Staleness is three refresh intervals (900s default, configurable). One missed
run on a busy shared host changes nothing; three means the scheduler is not
running and the figures must stop being presented as current.

A stored snapshot that cannot be parsed reads as **absent**, not as a partially
populated report: the missing halves would render as unknown while the surviving
halves looked authoritative.

### Tests

10 new tests. The three that matter most were **verified to fail against the
pre-correction controller** — probing restored inside the request — before being
trusted.

| Requirement | Test |
| --- | --- |
| no storage probe in a GET | `loading_the_dashboard_never_probes_storage` |
| no object-store access at all | `loading_the_dashboard_does_not_touch_the_object_store_at_all` |
| renders with providers unreachable | `the_dashboard_renders_when_every_provider_is_unreachable` |
| refresh records a snapshot | `the_refresh_command_records_a_snapshot` |
| probe failure → unknown | `a_provider_that_throws_while_being_probed_is_recorded_as_unknown` |
| missing snapshot → unknown | `a_missing_snapshot_reads_as_unknown_rather_than_healthy` |
| **stale never reads healthy** | `a_stale_snapshot_never_reports_healthy` |
| fresh passes through | `a_fresh_snapshot_passes_its_verdicts_through` |
| `checked_at` safe | `the_checked_at_timestamp_is_exposed_and_carries_nothing_else` |
| corrupt snapshot → absent | `a_corrupt_stored_snapshot_reads_as_absent` |

The storage double refuses every call *and* records it, so an accidental probe
surfaces as a failed page rather than as a list entry somebody must remember to
check. It implements the contract by hand rather than wrapping the final
`InMemoryStorageProvider`, so adding a method to the contract breaks it loudly
instead of leaving the tripwire silently unwired.

One test assertion of mine was wrong and was corrected rather than the code: it
searched the payload for the *word* "password", which a capability's remediation
text legitimately contains ("password resets and job failure notices depend on
it"). It now asserts against configured secret values — the same false-positive
class as the bare `key` and `path` matches caught earlier in this project.
