# UI-003c — Catalogue: contributors and compositions

The second and third catalogue resources, on the pattern UI-003a and UI-003b
established and had reviewed.

## Scope

Contributors and compositions, index and detail. **Assets are not in this PR**
and are not late: they carry the signed-preview boundary, which is a security
decision rather than another list, and it deserves its own branch, its own
review attention and a full budget. They follow immediately, from `main`, not
stacked on this branch.

## What it inherits, unchanged

Every guarantee the reviewed screens established, by construction:

- **Active identifiers only**, scoped at the read-model boundary. Never a global
  scope on `ExternalIdentifier` — audit and reconciliation code must keep being
  able to ask for revoked rows, and a test asserts it still can.
- **Filters refused, not ignored**: 422 at HTTP, `InvalidArgumentException` at
  the read model for every other caller.
- **Cursor pagination** on a natural key plus the UUID, shape-checked so a
  mangled URL is a refusal rather than a 500 inside the paginator.
- **No internal key** in any payload; UUID route binding.
- **Counts report what was returned**, never the configured cap.
- **Every `LIMIT` carries a deterministic `ORDER BY`.**

## The distinction this ticket is really about

`composition_contributor.share` is a **catalogue credit**. It records who wrote
what. It is **not** an ownership split and **not** a royalty entitlement.

That domain — RIGHTS-001 — does not exist yet. A screen that presented a credit
share as an entitlement would be inventing a financial fact, and it would be the
kind of invention that gets believed because it appears next to real data.

So the field is named `credited_share` everywhere it travels, both screens carry
a line saying these are catalogue credits and not ownership shares, and
`a_writer_share_is_a_credit_and_never_named_as_ownership` asserts that neither a
bare `share` key nor the words *ownership*, *royalty* or *entitlement* appear
anywhere in the payload. When the rights domain lands it brings its own model;
nothing here is to be reused as ownership.

## Contributors: legal name is not display name

They are different facts about a person, and the legal name is the more
sensitive one. It is exposed — the catalogue's purpose is establishing who is
credited on what, and a rights conversation that cannot name the party is
useless — but it travels under its own key and its own label rather than merged
into a single "name". Merging them is how a legal name gets published by
somebody who believed they were showing a stage name.

The list orders by `legal_name`, not `display_name`, because display name is
nullable and an ordering column that can be null puts an arbitrary subset of the
list in an arbitrary place.

## One small refactor

The cursor shape check now lives in `CursorShape`, shared by the four lists.
Extracted at the third copy, not the second: `TrackIndexQuery` and
`ArtistIndexQuery` were folded onto it in the same commit, and their existing
tests cover the change.

## Tests

**29 new tests. 692 PHP tests / 2675 assertions**, 1 skipped (the real ffprobe
run), plus 16 component tests.

Four regressions were injected deliberately and **six tests went red** before
the guardrails were trusted:

| Injected regression | Tests that caught it |
| --- | --- |
| active-identifier scoping removed | revoked identity (contributors, compositions), revoked-only ISWC |
| `shown` count reporting the cap | shown counts report what was returned |
| deterministic ordering removed before `LIMIT` | capped credit list is ordered and stable |
| `credited_share` renamed back to `share` | writer share is a credit, never ownership |

## Localisation

All new strings in en / fr / es / it / pt / de, including the contributor-type
and composition-role vocabularies and two new navigation entries.

## Architecture amendment

**None.** All four read models only read.

## Carried-over limitation

Unchanged and still true: a refused filter answers 422 with a JSON body rather
than an error rendered inside the filter form. Refusing loudly is what must not
regress; presenting the refusal nicely is a follow-up on the filter form itself,
and it now applies to four lists rather than two — which raises its priority.
