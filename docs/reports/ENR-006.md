# ENR-006 — The backlog nobody could reach

Item 19 of the Phase 2 order — scale, backfill and hardening. The gap it closes
was found by listing what every other module has and enrichment did not.

---

## The gap

`SuggestWhenTranscribed` only ever fires forwards. Every other optional feature
in this platform has a way back over what was already there:

| Module | Backfill |
|---|---|
| Media | `sanitube:media:analyze` |
| Transcription | `sanitube:transcription:backlog` |
| Deduplication | `sanitube:duplicates:evaluate` |
| Artwork | `sanitube:artwork:measure` |
| **Enrichment** | **nothing** |

So a catalogue transcribed before ENR-002 existed would never have received a
single suggestion, and the only route back was to **re-transcribe everything** —
paying twice to fix an omission.

---

## What was built

`sanitube:enrichment:backlog`, built like its transcription counterpart rather
than like a convenience, because it costs money: `--limit` defaults low rather
than to everything, `--dry-run` reports what would be sent, and the admission
gate is asked for the **whole batch** rather than per job — the failure being
guarded against is four thousand jobs landing on a queue a cron worker drains
once a minute.

`EnrichmentEligibility::hasModel()` was added so the command can say "no model
is configured" **once**, before walking a catalogue to be told the same thing
four thousand times. That is a property of the installation; every other refusal
is a property of one asset.

### What it does that the transcription command has no equivalent of

**It asks the spend guard before queueing.** ENR-003's guard was written for
exactly this scenario and its docblock says so: a backfill is bounded by the
queue ceiling in how many jobs sit there at once, and bounded by nothing at all
in how many reach a vendor over the following week.

Queueing into an exhausted ceiling would produce thousands of jobs that each
wake a worker, consult the guard and refuse — no cost at the vendor, a great
deal on a shared host.

**A dry run reports the ceiling rather than refusing on it.** A dry run that
stayed silent would tell an operator to expect work a real run would decline.

**It warns when the circuit is open**, without refusing — the cooldown may well
pass before a worker reaches the first job, but an operator watching a queue
drain into nothing deserves to know why.

## §1 — the two proofs

**A. COMPONENT PROOF.** `tests/Feature/Enrichment/EnrichmentBacklogTest.php`,
10 tests / 42 assertions. Most of them assert what the command *refuses* to do.

**B. PRODUCTION-PATH PROOF.** Every test runs the real command through
`$this->artisan('sanitube:enrichment:backlog')` — not the service behind it —
and asserts on what reached the queue. The command is registered in
`EnrichmentServiceProvider`, and `php artisan list sanitube` shows it.

### F7 — and a docblock that was overclaiming

Removing `whereNull('trashed_at')` survived because
`EnrichmentEligibility` refuses a trashed asset too. My own docblock said the
candidates are narrowed "by the eligibility service rather than by a second copy
of its rules in SQL" — while the query contained exactly such a copy.

The filter turned out to earn its place, for a reason the docblock had not
given: **`--limit` bounds the rows *read***. Without the pre-filter, a trashed
asset ordered first consumes the only slot and the eligible one behind it is
never reached — the sweep reports success having queued nothing, and running it
again does the same thing for ever.

So the test asserts that behaviour (and asserts the trashed asset really is
ordered first, or it would prove nothing), and the docblock now says *pre-filter*
and explains why, instead of claiming a purity the code did not have.

## What this ticket did not do

- **ADR-0015 / BULK-001c is not open, and an earlier draft of this report said
  it was.** Checking the ADR rather than the stale note in
  `docs/project-status.json` shows the decision was taken and accepted: the
  amplification factor is **measured at 2**, pinned by a passing test
  (`identical_bytes_are_currently_stored_twice_and_this_is_the_baseline`), and
  every option that removes the second copy either breaks AST-001's
  UUID-derived object key or destroys the record that a second import happened.
  It is reclassified `POST_V1_STORAGE_OPTIMIZATION`, not outstanding work. The
  stale `next_action` entry telling a future session to "pick an option, then
  implement it" is corrected in the same commit.
- **No screen.** Backfills are cron and console work; a button that spends money
  on four thousand assets needs its own confirmation surface.
- **No scheduling.** Whether this runs nightly is an operator's decision, and a
  command that scheduled itself would spend money nobody asked it to.
