# GEN-008 — the generation worker, and the path that never leaves it

ACE-Step's verified contract answers `POST /generate` with `output_path`: **a
path on its own filesystem**. Not bytes, not a URL, and the published contract
has no download endpoint — so SaniTube does not invent one (ADR-0018).

My first plan was for Core to open that path. That was wrong, and it was wrong
in a way worth recording: it would have required SaniTube Core and the GPU host
to share a filesystem. SaniTube must install on cPanel, on a small VPS, on
Alma/Rocky/Debian, on whatever an operator has. **A shared mount between a
shared-hosting account and a GPU server is not a requirement this platform may
make.**

So a worker sits between them, and the path stops there.

```
SaniTube Core                     (cPanel, VPS, anywhere — no GPU)
      │  authenticated HTTPS
      ▼
Generation Worker                 (the GPU host — SaniTube with a worker token)
      │  local HTTP
      ▼
ACE-Step                          (localhost, never exposed)
      │  writes output_path
      ▼
Worker opens, validates, streams
      │
      ▼
Shared object storage  ──storage key──▶  Core ingests → Asset → … → Candidate
```

---

## The rule

`output_path` is an implementation detail of the engine's host. It is **not**
persisted, **not** sent to a browser, **not** a SaniTube storage key, **not**
part of the generation domain, and it does **not** have to exist on Core's host.

Core is handed a *storage key* — a thing it already knows how to read from
anywhere. A test asserts the worker's output root appears in neither the
database row nor the rendered studio screen.

## What was built

| Piece | Side | What it is |
| --- | --- | --- |
| `ContainedPath` | worker | resolve, then compare — the whole security question |
| `AceStepEngine` + `HttpAceStepEngine` | worker | the published contract, field for field |
| `RunGenerationOnWorker` | worker | choose → render → contain → validate → stage → clean up |
| `POST /api/generation/worker/render` | worker | one route, one verb, behind its own token |
| `SelfHostedAceStepProvider` | Core | synchronous; talks to the **worker**, never to ACE-Step |
| `StorageGeneratedAudioReader` | Core | streams the staged object; falls through to HTTP |
| `CarriesRefusalCode` | both | lets a closed-set code cross the boundary |

No second worker architecture was created. There was no first one to reuse:
`src/Media` is **local process invocation** (`ProbeRunner` running ffprobe and
fpcalc on the same host), not a transport. This is the first worker boundary in
the platform, and it is deliberately generic enough — token middleware, one
module route file, storage-mediated payloads — for media to move onto later.

## Security

The engine tells us a path and we open it. Everything dangerous is in that
sentence, so `ContainedPath` is a class of its own — the piece most worth
testing, and the piece most likely to be "simplified" by somebody who has not
thought about symlinks.

**Resolved, then compared. Never compared, then resolved.** `realpath()`
collapses `..`, follows every symlink, and returns false for what does not
exist, so traversal, an absolute path from elsewhere, and a symlink sitting
innocently inside the root all fail one check.

| Refused | Code |
| --- | --- |
| `../` traversal, absolute path elsewhere, symlink escape | `OUTPUT_ESCAPED_ROOT` |
| a directory *inside* the root, a socket, a device | `OUTPUT_NOT_A_FILE` |
| reported success, wrote nothing | `OUTPUT_MISSING` |
| over the configured size — checked **before** the read | `OUTPUT_TOO_LARGE` |
| an extension this worker does not accept | `OUTPUT_UNEXPECTED_TYPE` |
| no output root configured — engine not even asked | `WORKER_OUTPUT_ROOT_NOT_CONFIGURED` |

The worker chooses the checkpoint, the GPU, the output root and the filename.
**No part of a request can reach any of them** — asserted behaviourally against
the body that actually leaves, including `GenerationRequest::$parameters`, the
field a careless caller would reach for.

Nothing shells out: the engine contract is HTTP and the file is opened by path
with PHP's own functions, so there is no command line for a filename to escape
from. Asserted with comments stripped, as `FinancialScopeTest` does.

Bytes are never buffered: `putFile()` to storage, `readStream()` back.

## WHO CALLS THIS IN PRODUCTION?

```
sanitube:production:run → ProduceForProductionSlot → StartMusicGeneration
  → SubmitMusicGenerationJob (queued worker)
      → SubmitMusicGeneration::execute
          → SelfHostedAceStepProvider::generate      [Core]
              → POST /api/generation/worker/render    [the boundary]
                  → VerifyGenerationWorkerToken
                  → GenerateOnWorkerController
                      → RunGenerationOnWorker → AceStepEngine → ACE-Step
  → SelectMusicGenerationResult → StorageGeneratedAudioReader → Asset → Candidate
```

The end-to-end test drives Core's outbound call **into this application's own
worker endpoint**, so the real middleware, form request and controller run. The
boundary is proved, not bolted over.

## The mandate's eight required proofs

| # | Proof | Test |
| --- | --- | --- |
| 1 | sync: slot → one call → ingested → no poll | `an_occasion_becomes_a_candidate_and_never_a_track` |
| 2 | async: submission → first poll dispatched | GEN-007 `an_asynchronous_generation_is_polled_and_until_now_nothing_started_it` |
| 3 | sync redelivery → one call | `a_redelivered_synchronous_generation_costs_one_render` |
| 4 | crash after completion → no re-render | `a_crash_after_the_render_does_not_render_again` |
| 5 | malicious `output_path` refused | four tests, one per escape shape |
| 6 | valid path → streamed into the Asset pipeline | proof 1, ending in a `TrackCandidate` |
| 7 | worker path never reaches browser or catalogue | `the_engines_path_never_reaches_the_database_or_the_browser` |
| 8 | Core boots with no worker | `core_boots_and_generates_nothing_when_no_worker_is_configured` |

Generated audio never becomes a `Track`. It becomes a `TrackCandidate` in the
same review queue an imported file joins, and proof 1 asserts `Track::count()`
is zero.

## Idempotency

Anchored in SaniTube's own generation identity — `submitted_at` on the
generation row — never in a provider reference. GEN-007 moved it; this ticket is
what makes the move load-bearing, because a synchronous engine returns no
reference at all and never will.

## Portability

Nothing hardcoded: worker URL, token, header, timeout, engine endpoint,
checkpoint, device, output root, size ceiling, allowed extensions, staging
prefix and every rendering parameter are configuration. `endpoint` has **no
default** — inventing `http://localhost:8000` would make a misconfigured worker
look like a working one until it silently talked to whatever else held that
port.

cPanel needs none of it. Unset token and URL is the shipped default: the worker
route answers 404, `isAvailable()` is false without touching the network, the
studio says so, and everything that is not generation carries on.

### ADR-0018's four conditions, answered in the guard

`ProviderProvenanceTest` refuses any new adapter until somebody updates its list
deliberately. The four answers are now written there: published by its supplier
(ACE-Step's own repository), read from a primary source, nothing reverse
engineered, and — the honest one — the **code** is Apache 2.0 while the model
weights' licence could not be read from this environment, so commercial rights
on output stay `UNKNOWN`.

### Mutation testing — 17 mutations, 17 killed

Killed: comparing before resolving (M1), dropping the path separator so a
sibling directory counts as inside (M2), skipping containment entirely (M3),
accepting a non-file (M4), no size ceiling (M5), leaving masters on disk (M6),
letting a caller's reference shape a filename (M7), staging any type (M8),
sharing the internal API's token (M9), claiming undocumented capabilities (M10),
storing a bare key as canonical (M11), reporting an unconfigured worker
available (M12), and four separate injections of request data into the engine
body — checkpoint, GPU, output path and step count (M13–M16).

**Two survivors, both real gaps, both now covered.** M4: my directory test used
the root itself, which is caught as an *escape*, so the `is_file` branch was
never reached — a sub-directory inside the root is the case that distinguishes
them. M13: I had scanned the form request's source but never the engine's
behaviour, so the single most important security property in the adapter was
untested. The replacement asserts the body that actually leaves.

`CODE READY`, and `CONFIGURED` is now reachable by an operator following the
deployment guide. **Not `CONNECTIVITY VERIFIED` and not `PRODUCTION VERIFIED`**:

proves the worker's own work, and proves nothing about the model.
