# OPS-003 — The doctor learns about the assisted features

Item 20 of the Phase 2 order. Six modules were built this session and none of
them was visible to `sanitube:doctor`, which is the command an operator runs on
a live server to find out what is wrong.

---

## What was added

A new `assistedFeatures()` section, and one design rule that governs all of it:

**Nothing here is ever a blocker.** Every one of these features is optional by
design — an installation with no AI account imports, catalogues, validates and
delivers exactly as before. Reporting an absent optional feature as a blocker
would make a correctly-configured shared host look broken, which is the failure
the whole capability model exists to avoid.

What the checks *do* report is the difference between **not configured** and
**configured and cannot work**, because those need different actions and only
one of them is a mistake.

| Check | What it says |
|---|---|
| `Transcription / provider` | Whether a provider is configured, and which. |
| `AI / provider` | The same for enrichment. |
| `Artwork / generation` | Whether the configured image provider can produce something this installation would accept. |
| `Production / unattended_release` | That nothing can hand a release to a distributor without a person. |

### The artwork check is the one worth having

ART-002 found that a provider can be configured, credentialled and working and
still be unable to satisfy this installation's own artwork requirements, because
the sizes it produces are smaller than `artwork.requirements.minimum_pixels`.
Left unreported, that is discovered as a refusal at the moment somebody wanted a
cover.

The warning names both numbers and both ways out — lower the requirement, or
declare a larger size the account actually supports. Both are legitimate, and a
check that only said "wrong" would have the operator guessing which.

### The unattended-release check is reassurance, not a problem

Reported at all because it is the thing an operator most needs to be able to
confirm without reading the source: nothing on this platform hands a release to
a distributor without a person. It reads `AutonomyMode` and asserts that no mode
reports `mayReleaseUnattended()`.

If that lock is ever removed, this becomes a **blocker** on a live server —
which is the right severity, and the only check in the new section that can
block.

### Secrecy

The provider checks report *which provider* is configured, because that is a
choice an operator made. They never report a key. The existing
`it_never_prints_a_secret` test was extended with all three new provider keys —
and, crucially, with an assertion that the provider *names* do appear, so the
three new negative assertions cannot pass on output that simply never mentioned
these features.

## §2 — mutation results

Six mutations. **Two survived; one was a real test defect and one was tested a
different way.**

| # | Mutation | Verdict |
|---|---|---|
| E1 | the size mismatch is never reported | killed |
| E2 | the longest edge used instead of the shortest | **survived → killed** |
| E4 | the unattended-release branch removed | see below |
| E4b | `AutonomyMode` unlocked at the enum | killed |
| E5 | the provider's key printed instead of its name | killed |
| E6 | the whole section dropped from the doctor | killed |

### E2 — square fixtures cannot catch a squareness bug

Every size in my fixtures was square, so taking the longest edge and taking the
shortest are the same number and the mutation survived. A provider offering
`1792x1024` has a shortest side of 1024, and reading the 1792 would report that
it can meet a 1500px requirement it cannot — a cover is square, so the short
edge is the one that has to clear the bar. A test with an oblong size kills it.

### E4 — the right mutation was on the enum, not on the check

Removing the `if` inside the doctor survives, because `mayReleaseUnattended()`
never returns true while the lock holds: the branch is unreachable *by design*,
which is the whole point of the check.

So the mutation was applied one level down instead — **E4b unlocks
`AutonomyMode` itself**, and the doctor's blocker fires. That is the correct
demonstration: the check is load-bearing against the thing it guards, and
proving it required mutating what it guards rather than the guard.

Recorded rather than withdrawn, because unlike this session's genuinely
redundant branches there *was* a mutation that killed it.

## What this ticket did not do

- **No new deployment documentation.** The cPanel and VPS guides do not yet
  mention the assisted features; they describe deploying the platform, and none
  of these is required to deploy it.
- **No unmeasured-artwork count.** The doctor could report how many verified
  covers have no measurement and point at `sanitube:artwork:measure`. It would
  need a query on every doctor run, and the doctor's read-only cheapness is
  worth more than the convenience. Named rather than quietly skipped.
- **No check that a configured provider actually answers.** That would mean the
  doctor making a billed API call, which violates its read-only, changes-nothing
  contract.
