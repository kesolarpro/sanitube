# UI-003a — Catalogue: tracks

The first slice of the catalogue interface: the track list and the track detail
screen, on real data, behind SEC-001.

## Scope, and what is deliberately not in it

UI-003 as specified covers five resources — tracks, artists, contributors,
compositions and assets — with an index and a detail screen each. **This PR
delivers tracks only**, and says so rather than presenting a fifth of the ticket
as the whole of it.

Tracks first because everything else in the catalogue is reached through them,
and because the two hard problems — cursor pagination that stays stable while
the catalogue is being written to, and a detail payload that leaks nothing about
storage — are the same problems the other four resources will have. Solving them
once, in a reviewed shape, is what makes the rest mechanical.

**Remaining, tracked as UI-003b:** artists, contributors, compositions and
assets, index and detail. `ArtistIndexQuery` and the rest follow the shape
established here.

## The read models

`TrackIndexQuery` and `TrackDetailQuery`. No CRUD controller, no Eloquent model
handed to a page.

**Cursor pagination ordered by `(title, uuid)`.** Offset pagination on a
catalogue that is being written to shows one row twice and skips another; on a
review screen that means an operator sees one candidate twice and never sees a
third. The tiebreaker is the UUID rather than the primary key on purpose:
Laravel encodes the ordering columns into the cursor, and that string travels in
the URL, so ordering by `id` would publish internal keys in every "next page"
link. `pagination_is_by_cursor_and_the_cursor_carries_no_internal_key` decodes
the cursor and asserts it.

**Filters are matched against the domain's own enums**, never passed through. An
unrecognised value narrows nothing rather than reaching the database — which
protects against a hand-edited query string becoming a SQL surprise and, more
subtly, against a list silently returning everything while the form still looks
filtered.

**Search is three `LIKE`s, not a full-text index.** MySQL, MariaDB and SQLite
disagree about full-text syntax and about which engines support it at all, and
this platform promises to run on all of them. At a catalogue in the thousands
that is not the bottleneck; if it becomes one, that is a decision to make with a
measurement. Wildcards in the search term are escaped, so searching for `%`
matches the literal character rather than returning the catalogue.

## What the detail screen is not allowed to know

A track's master asset knows its disk, its path and its original filename; the
analysis row knows the location it was read from and quotes it in
`failure_message`. **None of that reaches the browser.** Not because it is
secret in the cryptographic sense, but because a storage layout published in
page source is a storage layout that can no longer be changed, and a bucket name
in a screenshot is a bucket name in a support thread.

The checksum is abbreviated to twelve characters: enough for a human to compare
two rows, and the full digest belongs in an export rather than on a screen where
it will only ever be eyeballed.

There is no player and no download link. Handing the browser a URL to a master
is a decision for the asset screen, with a signed and expiring URL — not a
convenience to slip into a detail page.

## Cost

`listing_more_rows_does_not_cost_more_queries` counts queries at two list sizes
and asserts they are equal. **Verified to fail against lazily loaded relations**
before being trusted, as was the leak assertion against a payload with `disk`
and `path` added back.

## Typing

The pivot data is read through `TrackArtist`, `TrackContributor` and
`ReleaseTrack` rather than through `$model->pivot`. The pivot property is an
untyped bag that static analysis cannot check and a column rename would silently
break; the pivot models are real models with real casts. PHPStan level 6 passes
with no ignores.

## Localisation

All new strings in en / fr / es / it / pt / de, including the source and role
vocabularies. The completeness gate walks every file in `lang/en` in both
directions.

## Architecture amendment

**None.** No invariant, migration, column or relation is modified. Both read
models only read.

## Known follow-up, not a defect

Ordering is `(title, uuid)`; `title` is indexed and `uuid` is unique, but there
is no composite index over the pair. At the catalogue sizes SaniTube targets
this is not measurable. Adding one is a migration, which belongs in a CAT ticket
with a measurement behind it rather than in a UI ticket on speculation.
