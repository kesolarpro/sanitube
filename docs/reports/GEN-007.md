# GEN-007 — a provider may answer with the audio

GEN-001 wrote the music provider contract around one sentence:

> Generation is asynchronous by nature: `createGeneration()` starts a job and
> returns immediately; results are collected later by polling.

That was true of every supplier then in view, and it was **never verified
against one**, because none was reachable. GEN-006's research changed that: of
four candidates, exactly one had a contract this environment could read from a
primary source — ACE-Step 1.5, from its own repository — and it works the other
way round.

Re-read at the start of this ticket, per §7, from
`raw.githubusercontent.com/ace-step/ACE-Step/main/infer-api.py` (md5
`783d768bdb8f32255cd6e4ac65ed7e67`, 106 lines). Unchanged:

```
POST /generate  →  { status, output_path, message }
GET  /health    →  { status }
```

The call **blocks and returns**. No job identifier, no status endpoint, no
webhook, no cancellation.

See **ADR-0019**.

---

## The claim, and it is negative

**A synchronous provider never invents a job identifier.** Under the old
contract an adapter had exactly one road: mint an identifier for a job that had
already finished, store it, and answer polls about it from memory. Every part of
that is fiction, and fiction in an adapter is load-bearing by the time anybody
notices.

`provider_job_id` stays **null** for the life of a synchronous generation.

## What was built

| Piece | What it is |
| --- | --- |
| `GenerationProvider` | `name()` + `isAvailable()` — all a supplier must share |
| `MusicGenerationProvider` | asynchronous, unchanged, now a sub-contract |
| `SynchronousMusicGenerationProvider` | `generate()` returns the audio |
| `GenerationExecution` | finished-with-results **or** in-flight-with-a-reference |
| `ExecutionMode` | SYNCHRONOUS / ASYNCHRONOUS_POLLING / ASYNCHRONOUS_WEBHOOK / ASYNC_HYBRID |
| `music_generations.execution_mode` | provenance: why this row has no job identifier |
| `RecordGenerationResults` | one writer, shared by both roads |

`GenerationExecution` is constructible only through two named factories, so the
states the design exists to exclude — finished *and* holding a reference, or
neither — cannot be built. A completed execution with no audio is refused at
construction rather than discovered three services later.

## Capabilities stay structural

`SYNCHRONOUS` and `ASYNC_POLLING` join GEN-006's vocabulary and are read off the
sub-contract, not declared. Implementing an interface is a method that exists,
which is the strongest evidence short of running it. A supplier offering both
gets both — they are separate capabilities rather than one either-or field
precisely so that is expressible — and is asked the way that needs no second
call.

## WHO CALLS THIS IN PRODUCTION?

```
POST /studio/generations  ->  StudioActionController::startGeneration
  -> StartMusicGeneration (records, queues)
  -> SubmitMusicGenerationJob            (queued worker)
       -> SubmitMusicGeneration::execute ← the ONE place that branches on shape
       -> PollMusicGenerationJob         (async only)
```

The route did not change. What changed is that it now reaches a supplier of
either shape. A test asserts that exactly **two** files in the platform ask what
shape a provider has, and that they ask for different reasons:
`ProviderCapabilities` to *report*, `SubmitMusicGeneration` to *act*.

## Two defects found on the way

### 1. Nothing ever started polling

`PollMusicGenerationJob` re-dispatches itself while a generation is in flight,
and **nothing in the platform ever dispatched the first one** — `grep` found it
constructed only in a test. An asynchronous generation reached PROCESSING and
was polled by nobody, sitting in flight for ever with a supplier holding a
finished job.

Fixed in `SubmitMusicGenerationJob`, which is where the decision belongs: it
knows it is running in a worker, and the service does not.

### 2. Idempotency was keyed on a column a synchronous provider never fills

The early return and the atomic claim both guarded on `provider_job_id`. For a
synchronous supplier that column stays null for ever, so **every redelivery
would have called — and paid — again.** Both now guard on `submitted_at`, which
is written exactly when a request leaves this server, and is already what the
spend guard counts.

### 3. Two faults shared one sentence

Found by mutation. An asynchronous supplier that answers without an identifier
and a provider that implements neither contract were reported identically —
*"the provider cannot generate: it implements no execution contract"* — which
would send an operator to read the wrong file. Two faults, two sentences.

## Verification

- **14 tests, 41 assertions** in `tests/Feature/MusicGeneration/GenerationExecutionModeTest.php`
- Full suite: **1919 passed, 1 skipped, 24931 assertions**
- PHPStan level 6 clean, Pint clean, vue-tsc clean, Vitest 23 passed
- `SYNCHRONOUS` and `ASYNC_POLLING` translated in six languages

### Mutation testing — 10 mutations, 9 killed, 1 equivalent

Killed: inventing a job identifier (M1), the claim guarding on the wrong column
(M3), failing to recognise a synchronous provider (M4), accepting an empty job
identifier (M5), not recording the mode (M6), asking a dual-shape supplier the
expensive way (M7), never starting polling (M8), polling a synchronous or failed
generation (M9).

**M2 is equivalent** — the early return keyed on `provider_job_id` — because the
atomic claim catches everything it would, and M3 proves the claim is
load-bearing. This is the third occurrence of the same deliberate pattern
(PROD-004 M12, PROD-005 M2/M4): **the read is a suggestion, the guarded write is
the decision.**

M9 looked equivalent and was not: with its first guard gone, a *failed*
submission — which never records an execution mode — would fall past the mode
check and queue a poll per failure. Covered by its own test.

## State

`CODE READY`. No adapter: §7's condition is examined in GEN-008, which follows.
`ASYNCHRONOUS_WEBHOOK` and `ASYNC_HYBRID` are named and deliberately
unreachable — SaniTube has no generation webhook endpoint, and the vocabulary
exists so the day one is built, the word for what it produces is already here.

**REVIEW_REQUIRED**: this changes the provider contract's shape. ADR-0019
records the decision and its costs; a reviewer should read that first.
