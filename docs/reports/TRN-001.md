# TRN-001 — what a supplier heard, and what that is allowed to mean

## Where this sits

Phase 4 opens here. Deduplication answers "do we already have this"; enrichment
answers "what is in it". A transcript is the weakest thing this platform will
ever store, so this ticket is mostly about containment.

It ships the contract, the storage, the refusals and a test double. **It ships
no vendor adapter** — see below.

## A transcript is a suggestion, and the code says so

ADR-0016's third level. It was produced by a model that was not trained on this
catalogue, cannot be asked why, and is reliably wrong about proper nouns, about
languages it was not expecting, and about singing in general.

So `nothing_a_supplier_said_reaches_the_catalogue` asserts the containment
directly: after a transcription the asset row is byte-for-byte what it was, and
no track exists. In particular the detected language is **not** written to
anything — a release's language is an editorial decision with distribution
consequences, and a model that heard mostly instrumental will happily report
English.

## The hint and the guess are both kept

`language_hint` is what the operator believed; `detected_language` is what the
model heard. Neither resolves the other, and `contradictsTheHint()` surfaces the
disagreement.

That disagreement is the most useful thing the row can say. It is how a
mislabelled import gets noticed — and a design that let the guess overwrite the
hint, or the hint suppress the guess, would throw away the only signal.

## `none` is the default and a legitimate permanent choice

An installation that never configures a supplier ingests, deduplicates,
organises and distributes exactly as it would otherwise. It simply has no
transcripts.

The disabled provider **refuses rather than returning an empty transcript**. An
empty string is a result — the model heard nothing — and storing one would put a
row in the table asserting this asset contains no speech, which nobody
established. An instrumental and a failed decode look identical from here.

The `normaliseProviderName` asymmetry is copied from AI-001 deliberately: an
empty value, an unset variable, a blank line and the literal `null` all mean
`none`; a name with nothing behind it is an **error**. A misspelt supplier and a
deliberate absence are different things, and only one of them should be quiet —
otherwise an operator who configured `whispr` wonders for a week why nothing was
ever transcribed.

## The supplier gets a local path, never a URL

Everything is streamed to a temporary file first and removed in a `finally`,
including on failure — the case that fills a shared account's disk if nobody
writes it. Asserted twice: once that no temporary file survives a failed call,
and once that what the provider received contains no `://`.

That is a security property as much as a practical one. **No adapter can be
talked into fetching an arbitrary address on the platform's behalf**, because
none of them is ever given an address.

## Segments are rows, not a JSON blob

ADR-0002 forbids the JSON column builder platform-wide, but the better reason is
that segments are the part anybody will want to query: "what is said around
2:14" is a `WHERE` clause here and a full-table decode otherwise.

`start_ms`, `end_ms` and `position` are **signed** — they are arithmetic
operands, and ADR-0017 records what an unsigned column does to `end_ms -
start_ms` on MySQL and MariaDB.

They are also called segments and not lines. Providers segment on silence, on
punctuation or on a fixed window, and none of those is a lyrical line; naming it
one would make every screen above assume a structure the audio never had.

## Re-running

Idempotent by provider version: a second run against the same asset returns the
stored row without paying for the call, asserted by counting calls on the
double. A **version bump adds a row** rather than replacing one, so a later
comparison has something to compare against. A forced re-run at the same version
replaces the segments wholesale, because boundaries move between runs and a
half-updated timeline is worse than either version of it.

## Mutation testing

| Mutation | Test that failed |
|---|---|
| empty transcripts stored | `a_supplier_that_heard_nothing_leaves_no_row` |
| idempotency check removed | `running_again_does_not_pay_for_the_call_twice` |
| segments no longer replaced | `re_running_the_same_version_replaces_the_segments_rather_than_doubling_them` |
| operator's hint swallowed | `the_operators_hint_is_passed_through_and_kept_beside_the_guess` |
| disabled provider returns empty text | `the_disabled_supplier_refuses_rather_than_returning_an_empty_transcript` |
| unknown provider name silently disables | `an_unconfigured_supplier_is_an_error_and_a_blank_one_is_not` |

## Not in this ticket, and why

- **A vendor adapter.** Deliberate. An adapter is an API contract plus
  credentials plus a rate limit plus a cost model, none of which can be verified
  from here, and shipping an unverified one would mean a provider that reports
  `isAvailable()` and then fails on first use — exactly the "discover it through
  an exception mid-workflow" the contract exists to prevent. The manager refuses
  a configured name with nothing behind it rather than pretending.
- **A review screen.** Transcripts are stored and queryable; showing them, and
  letting a person accept anything from one, is its own ticket — and accepting
  is where the ADR-0016 rules get their real test.
- **Anything derived from a transcript.** No title suggestion, no language
  assignment, no lyric field. Each of those is a separate decision about
  promoting a suggestion, and none of them should arrive as a side effect of
  storing one.
- **Scheduling.** Transcribing an existing library needs the backlog circuit
  breaker, same as the deduplication backfill.
